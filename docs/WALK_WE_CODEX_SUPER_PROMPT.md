## 1. Product and source of truth

Walk We is a Thai-first, English-capable mobile PWA for people walking one-handed in central Bangkok. It compares shadier routes in daylight and **ปลอดภัยกว่า (ตามข้อมูลที่มี)** / **Safer (based on available data)** routes at night. The main experience is choose endpoints → compare options → follow the walk. Give users a short explanation of the tradeoff, legible turn instructions, and fast access to SOS. No account or user database.

Treat runtime code, tests, checked-in datasets and config as evidence of current behavior. Use `apps/web/PRODUCT.md`, `apps/web2/PRODUCT.md`, and `apps/web2/DESIGN.md` for the respective design intent. `README.md`, `ARCHITECTURE.md`, `AI_USAGE.md`, `TESTING_CHECKLIST.md`, `docs/shadow-regression.md`, and `docs/submission/` provide context. Check claims in older documents against the implementation. The first-run swipe introduction described in the old brief was removed, Recommended defaults to shadiest/safer as available, and SOS is limited to planner/navigation. DeePer is a historic interaction reference whose relevant patterns are already in this repo. The existing Walk We project can be maintained without access to DeePer.

## 3. App workflow shared by both versions

1. **Entry and setup.** `/` resumes an active session at `/navigate`, otherwise shows first-time landing or directs the returning user to `/setup` or `/plan` based on local flags. `/welcome` is a direct landing link. Start leads to a skippable safety setup for the walker’s optional callback number and up to five emergency contacts. Add contact fields on request, validate numbers locally, and let a judge select the sample BTS Siam → CentralWorld walk (`/plan?demo=1`) without entering a number. `/onboarding` redirects to setup. `/start` replays first run while retaining user data. Keep `/data`, `/contacts` and `/privacy` reachable.
2. **Choose points.** Map plus bottom sheet with peek, half and full positions and a desktop panel. Select either endpoint by search, pin or available current-location control. Use curated Thai/English pilot landmarks first and Photon for wider search. Include swap, Home/Work/Station slots, other saved places, and recent places. Use the selected place ID, display name and coordinates consistently. Explain permission before the first GPS prompt. If GPS is blocked, inaccurate, unsupported, or the page was opened inside a browser such as LINE’s, give a practical manual search/pin or browser fallback. A saved destination may reuse an already permitted GPS fix as its origin.
3. **Choose conditions.** Now or scheduled walk in `Asia/Bangkok`, independent of device timezone. Auto mode uses local sunrise/sunset; allow a day/night override. Keep display theme and trip mode distinct. Night routing exposes crowded, CCTV and lighting factors. Accessibility preferences include avoid stairs, read aloud, larger text and haptics. Expose a manual flow even with AI disabled.
4. **Compare routes.** Show reasonable loading and error states, fit to the selected route on the map, and show estimated time/distance, shade share or night score, stairs/closure hints where applicable, and a comparison to the shortest route. Select the first ranked route by default. Collapse identical and immaterial alternatives; allow one card. Label estimates and distinguish visual route runs with line style and a legend. The pilot app rejects straight-line trips beyond 5 km and filters computed routes beyond 5 km. Preserve inputs on return from results.
5. **Navigate.** Create a persisted session with route, endpoints, time, mode, steps, destination and current index. Generate localized turn instructions and attach the bidirectional Siam–CentralWorld guide only if geometry, direction and applicable hours match; fall back to computed instructions and the version’s step visuals. Offer reversible swipe and buttons, including the primary “I’m here” / arrival control, step count, ETA/progress, map toggle and exit confirmation. Manual progression must work without GPS. Start a high-accuracy watch only in navigation when already permitted; use the fix as context, and release the watch and wake lock when leaving. Preview or install offers must accommodate ordinary browsers and iOS instructions. Clear the active session on completion or confirmed exit.
6. **Offline.** Workbox precaches the shell and published datasets/guides. In `src/nav/prefetch.ts`, warm route-specific photo variants plus map styles, sprites, glyphs and route-area vector tiles in the background. Show readiness only after the service worker controls the page and required resources are ready. Test offline continuation and reload on the same step. Manual steps are essential; uncached external search, live voice and fresh tiles depend on availability. Render a usable sheet if MapLibre/WebGL fails.

## 4. Shared routing and data contracts

- Pilot bbox `[100.505, 13.725, 100.565, 13.768]` in west/south/east/north order, around Siam from Ratchathewi to Sam Yan and Pathum Wan to Phloen Chit. Build a local metre projection and a compact pedestrian graph, snap to the connected network with a bounded distance, and sample walkways at roughly 10 m. Default walk speed is 1.25 m/s. Retain error distinctions such as outside coverage, no path, too far and unavailable.
- **Day logic.** Use SunCalc at the departure instant; project shadows away from the sun with length `height / tan(altitude)`, guarded at low altitudes. Make height provenance explicit: OSM `height` → `building:levels × 3 m` → type/default estimate. Use `ShadeScene`, building geometry and spatial indexing, trees, overhead decks, and covered/indoor paths. Keep lazy per-edge shade calculation and memoization. Treat permanent cover as crucial in high sun. For routing, cloud cover tempers the sun penalty (`1 - 0.7 × cloudPercent / 100`); weather timeout or failure lets routing proceed. Shade percentage describes the computed route geometry/cover, not a weather guarantee.
- **Night logic.** Combine selected factors into risk from nearby CCTV, `lit`/lamps or estimated lighting, and road class plus nearby POIs as a proxy for crowding. Score out of 10 for comparison, with no real-time crowd, working-camera or personal safety guarantee. Expose source, date, license, sparse lighting and estimated heights in data limitations. Incidents use OSM way IDs and reviewed source/date/time/severity, with ~365 day half-life and 20% weight outside their active window. The released dataset in this checkout contains samples only.
- **A* rules.** Apply mall hours before scoring by mode (default Bangkok `10:00–21:00` when needed, must remain open through the conservative 20-minute routing window). Closed mall edges cannot be selected; retain per-step closure checks. Avoid stairs when possible; if no path exists, current soft fallback uses a `40×` penalty and must disclose remaining stairs. Peak shade/safety profiles are uncapped relative to the shortest inside the app’s absolute walk limit. Balanced is capped at `1.25×` the shortest. Cost is edge length scaled by the applicable sun/risk and incident penalties; the shortest is the baseline. See `packages/core/src/routing/router.ts` for profile weights. Fold alternatives unless meaningfully better (5 shade percentage points, 0.3 night-score points, or fewer active incidents). Keep route geometry, runs, distances, time, score and steps coherent when profiles merge.
- **Data workflows.** `packages/data/scripts/bake-area.ts` uses Overpass OSM walkways, buildings, trees, elevated decks, malls, lamps, POIs and OSM CCTV plus BMA CCTV, and emits validated `data/areas/siam.json` with per-layer provenance. Upstream bakes are deliberate, rate-aware maintenance tasks. `siam-prototype.json` is regression input only; `scripts/compare-prototype.ts` documents comparisons. `scripts/precompute-shade.ts` produces 30-minute shade samples for a representative day/month for future scaling. Runtime still computes routes and shade locally. `data/routes/siam-centralworld.json` defines both directions with bilingual instructions, landmark, coordinates, photo reference and optional valid hours. Replace placeholders with approved real photos of the exact steps under the existing names; `npm run photos` creates 480/960 px AVIF/WebP/JPEG and manifest/blur data. Preserve OSM ODbL and asset attribution. See config for BMA CCTV licensing status.

The checked-in photo manifest labels all nine guide assets as placeholders. Use its flags to decide what to show and disclose. Report verified photos only after the originals are replaced and the variants rebuilt.

## 5. Voice and API contracts

| Feature | Input and computation |
| --- | --- |
| Route explanation | `RouteWhy` compares the selected route with the shortest route using the distance, shade percentage or night safety score calculated on the device. |
| Speech input | The browser's `SpeechRecognition` or `webkitSpeechRecognition` fills the place search field in Thai or English. Hide the microphone when unsupported and keep typing available. The browser vendor may process microphone audio. |
| Speech output | The browser reads localized instructions and arrival messages aloud. When configured, `POST /speak` sends at most 300 characters and the language to ElevenLabs via the Worker, which returns MP3 audio. Keep the browser voice as the fallback. |
| Incidents | An operator adds reviewed entries directly to `data/incidents/bangkok.json` with the relevant OSM way IDs, source links and dates. Vite strips placeholder entries at build time. |

| Other dependency | Contract |
| --- | --- |
| OpenFreeMap + MapLibre | Day positron and night dark styles by env; vector tile attribution, lazy load and route-specific caching. |
| Photon | Search text and coarse bias (roughly 1 km); pilot landmarks help handle Thai names locally. Public service is fair-use; self-host or seek approval before switching to a paid provider. |
| Open-Meteo | Optional daytime cloud cover using coarse origin and walk time; tolerate unavailable data. |
| Browser + OS | User-initiated geolocation, optional navigation watch, Screen Wake Lock, vibration, Web Share, install APIs, SMS/LINE/tel links, clipboard and service worker; feature-detect and provide visible fallbacks. |
| Public app config | `VITE_MAP_STYLE_DAY`, `VITE_MAP_STYLE_NIGHT`, `VITE_GEOCODER_URL`, `VITE_WEATHER_URL`, `VITE_ERROR_TRACKING_URL`, `VITE_AI_PROXY_URL`. No browser secrets. Error reporting is optional and must redact sensitive data. |

## 6. SOS, sharing and local privacy

- Top-right SOS on `/plan` and `/navigate`; support touch/pointer and keyboard hold. One-second hold with progress → five-second full-screen countdown, large Cancel, optional cues → show the actions panel. Early release or cancellation must never open a messaging action. Time completion opens the panel only. Sending and dialing require an explicit user action in SMS, LINE, the system share sheet, or the dialer. Build the best available user-authorized location link and optional callback info, handle missing GPS/contacts, and show quick-dial numbers from city config (`191`, `1669`, `1155`). Keep focus and dismiss behavior usable in both themes. Never make a real emergency call/send as part of automation.
- Route sharing is a one-time location snapshot with destination and estimated arrival where available. Use LINE, Web Share and copy fallbacks. `LiveShareService`, `ArrivalWatch` and token generation are extension points only. Expiring live tracking, background tracking and missed-arrival alerts are outside the shipped feature set. Do not claim a locked browser keeps GPS running.
- Persist only the settings, saved/recent places, optional phone/contacts and active trip needed locally under existing storage keys. Keep the delete-local-data control and avoid building a walking history. Keep `/privacy` and `AI_USAGE.md` aligned with actual browser/vendor/provider data flows, including the difference between precise GPS, coarse provider bias, prompt text, and TTS. The existing privacy page’s vendor list should be checked against configured AI/voice behavior before release.
