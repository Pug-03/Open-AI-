# Walk We · แบบหน้าจอ Agentic AI

[เปิดต้นแบบกดดูแต่ละขั้น](UI_WIREFRAME.html) · [Architecture](ARCHITECTURE.md)

งานออกแบบนี้ต่อยอดหน้าวางแผนและนำทางของ Walk We 2 ใช้แผนที่เป็นบริบทและใช้ bottom sheet ให้ผู้เดินยืนยันข้อมูล เปิดหลักฐาน หรือดำเนินการต่อ ตัวเลขในต้นแบบใช้ข้อมูล fixture เพื่อแสดงลำดับการอ่านของหน้าจอ

## หน้าจอและตำแหน่ง

| พื้นที่ | สิ่งที่แสดง | พฤติกรรมที่ต้องทดสอบ |
| --- | --- | --- |
| **วางแผนเดิน `/plan`** | ต้นทาง ปลายทาง เวลาออกเดิน ตัวเลือกเลี่ยงบันได ช่องพูดหรือพิมพ์ และการ์ดยืนยัน Intent | แก้แต่ละช่องได้ ระบบถามเมื่อชื่อกำกวมหรือปลายทางอยู่นอกพื้นที่ ผลจากตัวแปลในเครื่องยังแก้และยืนยันได้ |
| **เทียบเส้นทาง `/plan`** | การ์ดแต่ละทางแสดงเวลา ระยะ และนาทีที่โดนแดด กลางคืนแสดงช่วงที่มีข้อมูลไฟและช่วงที่ยังไม่ทราบ | เปิดเหตุผลจากการ์ดช่องนั้น ทางเลือกแนะนำแสดงที่มาจาก Worker เมื่อโมเดลหมดเวลา |
| **เวลาออกเดิน** | แถบเวลาภายใต้การ์ดกลางวัน เปรียบเทียบเวลาออกเดิมกับเวลาที่ลดแดดได้และยังทันถึง | เปลี่ยนเวลาเมื่อผู้เดินกดเลือก แสดงเวลาถึงของแต่ละตัวเลือกพร้อมกัน |
| **หลักฐานและถามต่อ** | Bottom sheet จากการ์ดเส้นทาง แสดงช่วงถนน สถานะไฟ แหล่งข้อมูลและเวลาตรวจ หากสมมติฐานเปลี่ยนทางเลือก ให้แสดงคำถามหนึ่งข้อ | ผู้เดินเลือก preference หรือข้ามได้ แสดงคำอธิบายจาก snapshot เดียวกัน เปิดค้นเพิ่มแล้วแสดงผลเป็นร่างรอตรวจ |
| **สนทนาด้วยเสียง** | แผงเสียงจากหน้าวางแผนและหน้าทริป แสดงสถานะฟัง กำลังตรวจ รอคำตอบ และหยุด พร้อมข้อความที่ทำต่อได้ | เริ่มไมค์หลังผู้ใช้อนุญาต การขอแชร์เปิดหน้าขอยืนยัน การขอช่วยเหลือเปิดแผง SOS |
| **ระหว่างเดิน `/navigate`** | แนวทางถัดไปกับแถบ Companion เมื่อมีเหตุจริง เช่น ทางเชื่อมปิดหรือพบช่วงไฟที่ไม่มีข้อมูล พร้อมปุ่มดูทางเลือกและใช้ทางเดิม | แอปส่งเหตุเข้า Companion ผู้เดินเป็นคนยืนยันการเปลี่ยนทาง และกด SOS ได้จากตำแหน่งเดิม |
| **หลังถึงจุดหมาย** | สรุปทริปและคำถามสั้นเรื่องช่วงถนนที่ข้อมูลขาด มีปุ่มส่งรายงานและข้าม | บันทึกเป็นร่างรอตรวจ แสดงว่าได้รับรายงานแล้ว |
| **งานทีม** | หน้าคิว Steward และข่าว/Voice Research สำหรับผู้ตรวจ แสดงหลักฐาน แหล่ง URL เวลา สถานะ และให้อนุมัติหรือปฏิเสธ ส่วน trace และ eval แสดงในมุมมองสำหรับทีม | ตรวจสิทธิ์ก่อนเปิดคิว ผูกผลกับ `datasetVersion` และแสดงสาเหตุ fallback โดยไม่บันทึกข้อความส่วนตัวหรือพิกัด |

## สถานะที่ต้องออกแบบร่วมกัน

- **กำลังคำนวณ** คงแผนที่และค่าที่ผู้ใช้ยืนยันแล้วไว้ ปุ่มยกเลิกกลับมาแก้ขอได้
- **ต้องถามผู้ใช้** ถามทีละเรื่อง เช่น «ยอมเดินเพิ่มไหมเพื่อเลี่ยงช่วงที่ยังไม่มีข้อมูลไฟ» แสดงระยะและเวลาจาก Worker ใต้ตัวเลือก
- **หมดเวลา** ใช้ผล Worker ที่ตรวจได้และแสดง «คำนวณจากข้อมูลเส้นทาง» ปุ่มเริ่มเดินยังทำงานได้เมื่อมีเส้นทาง
- **หลักฐานไม่ครบ** ใช้คำว่า «ยังไม่มีข้อมูล» พร้อมเส้นประและข้อความ แยกสถานะนี้จากช่วงที่ยืนยันว่าไฟไม่ติด
- **SOS** ใช้แดงสำหรับปุ่มช่วยเหลือ ประกาศช่วงกดค้าง นับถอยหลัง และยกเลิกได้ แสดงโหมดซ้อมแยกจากการแชร์จริง
- **การเข้าถึง** ปุ่มสัมผัสอย่างน้อย 44 × 44 px มีข้อความกำกับสีและเสียง ลำดับ focus ตามลำดับอ่าน ใช้ธีมกระดาษสีฟ้าอ่อนในกลางวันและน้ำเงินเข้มในกลางคืนตามแบบเดิม [Walk We 2 Design](../../apps/web2/DESIGN.md)
